# Decisions

Record every ambiguity resolved while implementing `PLAN.md`, and every dependency added outside the plan's stack table.

| # | Date | Decision | Reason |
| --- | --- | --- | --- |
| 1 | 2026-11-17 | The app is built in thin vertical slices, in the order agreed at Gate 1. It is not built phase by phase. Slice 1 is one D reading drill from Today to a stored result, offline. Slice 2 is onboarding, Settings and backup. Then come Höra, vocabulary, grammar, Skriva, Tala, everyday scenarios, mocks with Today and Progress, and hardening. | Kul approved this order. It gives a working app after the first slice instead of after five phases. |
| 2 | 2026-11-17 | Configuration and shared code are copied from `workout-tracker-pwa` and adapted. Nothing is shared as a package. | Matches the plan's reuse list. Two copies can change independently. |
| 3 | 2026-11-17 | The database is named `learn-swedish`. The storage-failure event is `sfi-storage-failure`. The base path is `/learn-swedish/`. | Both apps share the origin `imkulwant.github.io`, so storage names must not collide. |
| 4 | 2026-11-17 | Database version 1 declares every table in the plan: `attempts`, `cards`, `writings`, `recordings`, `mocks`, `studyDays` and `settings`. Only `attempts` and `settings` are used in slice 1. | A later slice can then use a table without a schema migration. Indexes on the unused tables can still change in a new version. |
| 5 | 2026-11-17 | Content schemas and validation live in `src/domain/content/`. Both the app and `scripts/build-content.ts` use them. The script runs with Node's built-in TypeScript type stripping, so domain files import each other with `.ts` extensions. | One definition of valid content, with no copy to drift. Node 26 runs `.ts` files directly, so no extra build tool is needed. |
| 6 | 2026-11-17 | Add `yaml` (dev, ISC) to parse content sources. | Reviewers read and edit YAML more easily than JSON. It runs only at build time and is not in the app bundle. |
| 7 | 2026-11-17 | Compiled content (`public/content/`) is generated by `npm run content` and not committed. `build` runs it first. `predev` runs it with `INCLUDE_DRAFTS=1`. | The YAML sources are the single source of truth. |
| 8 | 2026-11-17 | Production builds ship only reviewed texts. CI deploys a production build, so **the deployed app shows no reading packs until a reviewer approves pack `d-lasa-1`**. The e2e tests build with `INCLUDE_DRAFTS=1`. | This is the plan's review gate. To preview drafts on the live site, set `INCLUDE_DRAFTS: '1'` on the build step in `verify.yml`. That is a deliberate choice for Kul to make. |
| 9 | 2026-11-17 | The KP27 coverage check fails only for the "Lyssna och läsa" points (in `content/content.test.ts`). The build prints the other uncovered points but does not fail on them. | The plan says a coverage test fails when a point has no items. Points for speaking, grammar and the like belong to later slices. The check gets stricter as each slice lands. |
| 10 | 2026-11-17 | Reading item types in slice 1 are multiple choice (`mc`), open answer (`short`) and matching (`match`). Matching covers both "Para ihop frågor och svar" (numbered options) and "Vem tycker vad?" (name options). An option with more than 24 characters switches the picker to numbers with a list above it. | These are the formats in Skolverket's example tasks. A native `<select>` gives the iOS picker and works with screen readers. |
| 11 | 2026-11-17 | A matching item scores one point per pair, and readiness weighs every attempt by its points. An open answer that matches no accepted answer is judged by the learner against the model answer, and stored as `selfMarked: true` with full weight. | This follows the plan's readiness and answer-check definitions. Self-marked answers keep their full weight for now; the plan does not say to discount them. |
| 12 | 2026-11-17 | The drill keeps its position (which text is shown) in memory only. Each answer is written to IndexedDB the moment it is checked. A reload starts the pack again from text 1, and earlier answers are kept in history. | Answers are never lost. Resuming a drill in the middle is not in slice 1, and mocks will need resume anyway (slice 9). |
| 13 | 2026-11-17 | The app is named **SFI Prep** for now, with a new icon: a blue speech bubble with a yellow check. The accent colour is yellow `#ffcd3c`. | The plan's working name. The name and icon can still change before release. |
| 14 | 2026-11-17 | The error screen and the storage-failure dialog offer only Reload until backups exist in slice 2. | Backup export is part of slice 2. |
| 15 | 2026-11-17 | `attempts` is indexed `id, itemId, [level+skill], answeredAt`. The plan listed `packId, skill, level, mode, finishedAt`. Readiness reads one level and part, then sorts in memory. | Every read so far is by level and part. Per learner that is a few thousand rows a year, so sorting in memory is cheap. If it ever shows, switch to a `[level+skill+answeredAt]` index with `.reverse().limit(40)`. |
| 16 | 2026-11-17 | A question shows its verdict only after its answer is stored. A failed write shows "Your answer could not be saved. Try again." and leaves the question open. A refused write (quota and the like) also opens the storage-failure dialog. Readiness percentages are rounded down. Open answers also ignore curly quotes and dashes at either end. | These came out of the slice 1 code review. Feedback without a stored answer would be a false saved state. A rounded-up number could show "75% · Almost ready". iOS Smart Punctuation types curly quotes. |
| 17 | 2026-11-18 | The welcome screen takes the place of Today until it is completed, and it asks only for the level and an optional test date. Deep links (for example a reading pack) open without it. The plan's 20-item placement check is not built yet. | A placement check needs C content, which does not exist yet. Keeping deep links open avoids a gate in front of every screen. |
| 18 | 2026-11-18 | A backup holds `attempts` and `settings` only (format `sfi-prep-backup`, schema version 1), as those are the only tables in use. Merge adds the answers this device lacks, since answers never change, and keeps the newer copy of each setting. Replace swaps both tables in one transaction. Files over 20 MB are refused before they are read. Unknown fields and unknown settings make a file invalid. | Same rules as the workout tracker's backups, simplified for rows that are never edited. New tables join the format with a new schema version. |
| 19 | 2026-11-18 | The backup reminder appears when the oldest answer given after the last backup is more than 14 days old. With no backup yet, every answer counts. A backup file records itself as the last backup, so a phone restored from it does not ask again. A merge never takes `lastBackupAt` from the file. | Nothing unsaved means nothing to nag about. The first version counted from the last backup even when nothing had been answered since, which the code review caught. |
| 20 | 2026-11-18 | Losing data is detected with `localStorage` key `sfi.hadData`. It is set after the first stored answer, at a launch with answers, and after importing answers. At launch, the restore screen shows if the key is set but no answers are stored. | Same mechanism as the workout tracker, with its own key on the shared origin. |
| 21 | 2026-11-18 | The level and test date in Settings show a change at once. Once the write has finished, the next value read from the database takes over, and a failed write shows an error and goes back to what is stored. The date field keeps half-typed text locally and saves only a whole date from the year 2000 on. | A field tied only to the stored value snapped back until the database answered. A field that kept its own value could hide an import or a failed write. A desktop browser reports half-typed years such as 0002. |
| 22 | 2026-11-18 | Accessibility e2e scans run with reduced motion. | A scan during the 150 ms fade-in measured low contrast, so the test sometimes failed for no real reason. |
| 23 | 2026-11-18 | Every way to save a backup uses one `SaveBackupButton`: Settings, Save a copy first before Replace, the error screen, and the storage-failure dialog. When iOS refuses the share because the tap is too old, the button keeps the file and becomes "Save file". | The code review found the last three ignored a refused share, so on iPhone they did nothing at the moments a backup matters most. |
| 24 | 2026-11-18 | Backup files are refused if they contain an id over 200 characters, a time beyond what a JavaScript date can hold, or a time more than a day in the future. Error messages are cut to 120 characters. Replacing everything with a backup that has no answers clears `sfi.hadData`. | These come from the security review: a future time could hide the reminder or win every later merge, and a huge id was echoed in the error. An empty replace otherwise looked like lost data at the next launch. |
| 25 | 2026-11-18 | Known and accepted: `imkulwant.github.io` is shared with the workout tracker. Any script on that origin can read and change this app's IndexedDB and `localStorage`. Unique names prevent collisions but do not isolate the two apps. | Real isolation needs another origin, such as a custom domain, which would mean a backup and restore for existing users. Both apps are Kul's own and have no third-party scripts. |
| 26 | 2026-11-18 | Listening audio is made with Piper TTS 1.8.0 and two Swedish voices from `rhasspy/piper-voices`: `sv_SE-nst-medium` (licence CC0) and `sv_SE-alma-medium` (CC BY 4.0, credited in Settings → About). Both are trained on the NST Swedish speech database. `sv_SE-lisa` is not used, because its model card states no licence. The macOS voice Alva is not used, because Apple's terms limit redistributing what it produces. | These were checked against the model cards on 2026-11-18. The two voices differ clearly (measured median pitch about 76 Hz for nst and 191 Hz for alma), so dialogues have two distinguishable speakers. How natural they sound has not been judged by a person yet. |
| 27 | 2026-11-18 | Piper (GPL-3.0) is a build tool only, installed by `scripts/setup-audio.sh` into the gitignored `.tools/`. The audio it makes is committed in `public/audio/`, so CI and the content build never run it. The install lives under the project because Piper's speech engine (espeak-ng) failed to find its data under a ~180-character scratch path. | The app ships the audio files, never the program. Keeping the generated files in the repository keeps CI free of Python and machine-learning models. |
| 28 | 2026-11-18 | Clips are AAC in `.m4a`, mono at 48 kbit/s, encoded with macOS `afconvert`. A clip is its lines read in turn, with 0.35 s between lines of one voice, 0.7 s when the voice changes, and 0.4 s at each end. A line may carry a `say` form for the voice, such as "kvart över nio" for 9.15, and the transcript shows `text`. | AAC plays in every current browser. `afconvert` comes with macOS, so the build needs no ffmpeg. Piper reads digits and abbreviations unreliably, so numbers are spelled out for the voice. |
| 29 | 2026-11-18 | `content/audio.lock.json` keeps a fingerprint per clip of its voices, spoken words, kind and `SYNTH_VERSION`. The content build refuses a shipped clip whose audio is missing or whose fingerprint does not match. `npm run audio` remakes only the clips that changed. | An edited line can never ship with old audio. Changing a transcript-only field (`text` with a `say`, a speaker name, or the questions) does not remake audio. |
| 30 | 2026-11-18 | Audio is not precached. The service worker answers `/learn-swedish/audio/*.m4a` from the `sfi-audio-v1` cache, cache first, with byte ranges. A clip is stored when it is first played, and the Höra screen's "Download audio" stores a whole level. The route matcher is a RegExp built at config time. | Precaching would make every install download every clip. Safari asks for audio in byte ranges, which must be answered from the full stored file. A function matcher was copied into the service worker without its `base` variable and never matched, which the offline e2e test caught. |
| 31 | 2026-11-18 | The player has no seek bar, counts plays, and offers 0.75× and 1× speed, with unlimited plays in drills. The transcript opens only once every question of the clip is answered. | On the test, a clip is heard from the start. How often the test plays each clip is still unconfirmed (see the plan), so drills do not limit plays yet. Mock exams will. |
| 32 | 2026-11-18 | Reading and listening drills share one `DrillRunner`, and pack lists share one `PartScreen`. `PackSummary.textCount` is now `unitCount` (texts or clips), and listening packs list their audio files and total size in the manifest. | This avoids two copies of the drill flow, its answer storage and failure handling. |
| 33 | 2026-11-18 | Colour transitions on buttons and chips are turned off when the device asks for reduced motion. | That is the correct behaviour for those users. It also stopped an accessibility scan from sometimes measuring a chip mid-transition. |
| 34 | 2026-11-18 | Audio sources live in `content/audio/<clip>.m4a`, committed. The content build copies only the audio of shipped clips into `public/audio/` (generated, gitignored), as `<clip>-<fingerprint>.m4a`, and lists those paths in the compiled pack. The app deletes stored audio the current manifest does not list. The build fails on an audio file no clip uses. `npm run audio` writes each lock entry right after its clip, and removes audio and lock entries of deleted clips. | From the slice 3 code review: with fixed names, the cache-first service worker kept serving a clip's old audio forever after an edit. Draft audio was deployed and could be fetched by guessing its address. A failed run could leave a lock entry claiming new audio. |
| 35 | 2026-11-18 | The audio player counts a play only once audio actually starts, ignores a Pause tapped before audio began, and remembers the chosen speed (`playbackRate`, which is also in backups). After a failed load it says so and offers Reload instead of retrying in place. | An in-place retry could not be made to work in WebKit within the time limit, so Kul chose the simple message. WebKit keeps a failed load on an `<audio>` element even once the file can be fetched again, and after a failed `play()` it reports the element as not paused. |
| 36 | 2026-11-18 | Vite's chunk-size warning is raised to 900 kB. The enforced budget stays at 250 KB of gzipped JavaScript. | The app is one chunk of about 504 kB minified and 150 KB gzipped. Vite warns at 500 kB of uncompressed size, which is not the budget this project tracks. |
| 37 | 2026-11-18 | Add `ts-fsrs` 6.0.0 (runtime, MIT, open-spaced-repetition) for word scheduling. It is used as FSRS-7 through `DefaultScheduler`, with target retention 0.9 and no fuzz, so the same answers always give the same schedule. Its defaults put a new card answered Good about 5 days out. | This is the plan's choice of library, now at its current major version. Version 6 replaced the v5 API, so `src/domain/srs.ts` wraps it and nothing else imports it. |
| 38 | 2026-11-18 | A word card (`VocabCard`) stores times as epoch milliseconds and keeps the scheduler's other fields in `memory`. It is converted to and from the scheduler's own card, which uses `Date`s and is rejected when read back from JSON, at the boundary. The number of answers (`reps`) is the card's version, so a second answer to the same version, from a double tap or another tab, is ignored. | IndexedDB and backups need plain values. `updatedAt` alone could not tell two answers in the same millisecond apart. |
| 39 | 2026-11-18 | A word starts as a Swedish-to-English card. After one correct recognition (Hard, Good or Easy), an audio-to-meaning card opens. After two, an English-to-Swedish card opens. Both are due at once. The daily limits are 15 new words and 150 answers. Due cards come first, oldest first, then new words in pack order. A card in learning that comes back later today is waited for. A word counts as new for the day as soon as it is shown. | These follow the plan's card types and limits. Opening a new direction only once the word is recognised keeps the harder directions for words the learner has started to know. |
| 40 | 2026-11-18 | Database version 2 indexes `cards` by `dueAt` (version 1 declared `due`, unused). `studyDays` rows are `{ date, reviews, newWords }`, written in the same transaction as the answer they count. | The index now matches the field name. Version 1 never stored a card, so the upgrade copies nothing, and a migration test opens a version 1 database. |
| 41 | 2026-11-18 | Backup format version 2 adds `cards` and `studyDays`. Version 1 files still import, with no cards. Merge keeps the card with more answers (a tie keeps the stored one) and the larger count of each study-day field. Due times are only bounded, never refused as being "in the future". | Word progress must survive a phone move. A card's `dueAt` is meant to be in the future. |
| 42 | 2026-11-18 | Word packs (`skill: ord`) live in `content/vocab/`. Each word lists a fixed number of forms per part of speech (`FORM_COUNT`). A noun starts with en/ett and a verb with att, and the build checks both. The same headword may not appear in two packs. A learner aiming for D practises C and D packs, C packs first. Each word gets one audio file of its first form (or `say`), read by the `alma` voice, made and fingerprinted like clips. | One shape per part of speech lets the card show every form with a label. Checking en/ett and att catches the most likely authoring slip. |
| 43 | 2026-11-18 | Deferred: tapping a word in a reading text to add it to the deck. | It needs matching an inflected form in a text (for example "lönen") to its headword. That deserves its own design, and is better done once the lexicon is larger. |
| 44 | 2026-11-18 | From the slice 4 code review: every card shown counts towards the 150 answers a day, new words included. The due count on Today and Learn is capped at the answers left. A listening card waits until its word's audio is on the device. Start stores all word audio first (about 10 KB a word), waiting at most 3 seconds. After revealing an answer, focus moves to Good, and after each answer to the new card. Imported word cards must have an id that matches their word and direction, and finite non-negative scheduling numbers. Clip and word audio ids are checked for collisions. | New words could go past the daily limit. Offline, a listening card could not be answered honestly without its audio. Focus was lost each time the button under it was removed. A corrupt card could have stopped every session. |
| 45 | 2026-11-18 | Grammar lessons are written in a small Markdown subset (`## heading`, paragraphs, `- ` lists, tables, `**bold**`, and `*Swedish*` for Swedish examples), parsed by `src/domain/lessonText.ts` into a tree that React renders. The build refuses text outside the subset. `marked` is not used. | The plan named `marked`. Installing it was refused by this session's permission check, and a 130-line parser with tests covers what lessons need without a new dependency or any HTML. `marked` can still replace it later. |
| 46 | 2026-11-18 | Grammar packs (`skill: grammatik`) live in `content/grammar/`. Exercise types are multiple choice (reused, for linking words), `order` (tap chunks into a sentence), `gap` (type one form into a sentence) and `transform` (rewrite a sentence). Order exercises are shuffled the same way on every visit, seeded by the item id, and never shown in a right order. | These are the plan's four exercise types. A fixed shuffle keeps the screen stable across reloads and makes tests repeatable. |
| 47 | 2026-11-18 | Grammar answers are checked strictly against the listed answers, after the usual normalization (case, spaces, surrounding punctuation). There is no self-marking. | A form is right or wrong, and a learner cannot reliably judge their own grammar. The cost is that a correct answer missing from `accept` is marked wrong, so authors and the reviewer must list every right answer. |
| 48 | 2026-11-18 | Grammar answers are stored in `attempts` with `skill: grammatik` (`ATTEMPT_SKILLS`), so they are in backups without a new table. Backup format stays version 2; it now also accepts `grammatik`. Readiness reads only the four test parts, so grammar never changes it. A lesson counts as done once each of its exercises has been answered, right or wrong. | Lesson progress can be derived from answers, so nothing new is stored. An older app refuses a file with grammar answers as invalid, which is acceptable for one user on one deployed version. |
| 49 | 2026-11-18 | Grammar pack 1 is level C, so learners aiming for C and for D both get it, C packs first (`practiceLevels`, shared with words). Pronunciation drills are deferred to the speaking slice. | V2, BIFF, the perfect, definite forms and linking words are needed at both levels. Pronunciation drills need the microphone recorder that the speaking slice builds. |
| 50 | 2026-11-18 | Writing packs (`skill: skriva`) live in `content/writing/`. A prompt has its register (informal or formal), the task and points in Swedish, and a model answer at pass level with notes; each note's quote must appear in the model answer, and the model answer must fit the suggested length. The first D pack has two informal and two formal tasks. | At D the test has two writing tasks, one formal. Annotated model answers are the plan's feedback for writing in v1. |
| 51 | 2026-11-18 | The suggested length is 50–150 words at C and 80–200 at D (`WRITING_WORDS`). It is the app's own guide, not a confirmed exam figure, and the check panel only says "check this" outside it. | The plan lists the expected length of writing tasks as unconfirmed. These ranges are tuned by hand, to be replaced once the reviewer or SU confirms them. |
| 52 | 2026-11-18 | A text is a `writings` row. It is stored 400 ms after typing pauses, when the app is hidden (`visibilitychange`, `pagehide`) and when the screen is left; saves run one after another so one draft is never created twice. Handing in fixes the text; a later save of that text is ignored. "Write it again" starts a new row, so every assessed text stays stored. | A force-quit on iOS gives no warning, so typing must reach IndexedDB within moments. A fixed text keeps a self-assessment true to what was assessed. |
| 53 | 2026-11-18 | The self-assessment has six criteria from the KP27 D pass criteria (the task, the reader, structure, linking words, grammar, variation), each 0–2. Skriva readiness is the mean of the latest five assessed texts of the level, needs three, uses the same bands as Läsa and Höra, and says it is self-assessed. | The plan's rubric "6 criteria, 0–2 each" and its readiness definition for Skriva. |
| 54 | 2026-11-18 | The check panel (`src/domain/writingChecks.ts`) runs when the learner asks, not while typing. The V2 and BIFF checks are word patterns tested against `content/check-sentences.yaml`, which the reviewer approves. "sedan" and "då" are not treated as place-1 words, because "Sedan jag flyttade…" is right. | Hints that change with every keystroke distract while writing. Pattern checks will miss mistakes and sometimes flag right sentences, so they are worded as "check this", and their test sentences are content to review. |
| 55 | 2026-11-18 | Backup format version 3 adds `writings`. Version 1 and 2 files still import, with no texts. Merge keeps the copy of a text with the later `updatedAt` (a tie keeps the stored one). | Texts change until they are assessed, unlike answers, so the latest change wins. |
| 56 | 2026-11-18 | Deferred: the optional writing timer (it comes with the mock exam timers), and an archive of past texts (the Progress slice). Sharing a text uses the existing file share, as a `.txt` file. | The timer needs the stored end times that mocks bring. The share sheet with a file works on iPhone without new platform code. |
